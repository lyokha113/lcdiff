## LCDiff v0.3.12

Workspace and cumulative temporary-merge release focused on practical file
actions for archive comparison and merge workflows.

### Changes

- Allows editing text entries that exist on only one side in Compare mode.
- Adds Expand all and Collapse all controls to View mode.
- Adds session-only temporary JAR/ZIP targets using either an empty archive or
  a copy of the current archive.
- Keeps the temporary target fixed while either source side can be replaced
  repeatedly, allowing changes from multiple archives to accumulate.
- Supports conflict preview, per-entry or bulk decisions, explicit Apply,
  Save As, Discard, and retry-only recovery flows.
- Protects the replaceable source from legacy copy, hunk, drop, navigation,
  save, and close actions while a temporary target or recovery owns it.
- Documents and verifies the complete three-source workflow, Light/Dark UI,
  typed IPC parity, and archive-only creation boundary.

### Semantics

- Temporary merge is session-only until Save As succeeds.
- Merge behavior is based solely on archive paths and bytes; it does not apply
  build-system, dependency, class-loading, or domain-specific merge logic.
- Skipping a conflict preserves the bytes already present in the temporary
  target; it is not a delete action.

### Validation

- Frontend architecture, build, 526 tests, render, branding, and documentation
  verification.
- Rust formatting, clippy, and 214 workspace tests, including repeated Save As
  recovery and cumulative three-source smoke coverage.
- Java 17 sidecar smoke covering all bundled decompile/disassembly engines.
- macOS debug application and DMG build with bundled sidecar launch proof.
- Windows installer/MSVC runtime verification remains a Windows-runner gate.
